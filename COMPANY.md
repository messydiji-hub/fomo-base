# Engineering Standard

FOMO Base follows a technology-company operating model: clear ownership, reviewable changes, secure credentials, reproducible builds, and concise documentation.

## Commit Standard

Commits should read like they came from a serious product engineering organization:

- Use conventional prefixes: `feat`, `fix`, `docs`, `chore`, `refactor`, `build`, `ci`.
- Explain business or platform impact when relevant.
- Keep changes scoped and reviewable.

## Initial Platform Commit

This repository starts with a product-grade base identity and documentation layer so future engineering work has context before code lands.
